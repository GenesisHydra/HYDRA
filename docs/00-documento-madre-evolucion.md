# Documento Madre – Evolución del Ecosistema HYDRA

## Modelo Económico Oficial del Ecosistema HYDRA

### 1. HYDRAS FUNDADORAS
- Las tres HYDRAS fundadoras son:
  - Financial
  - Design
  - Trading
- Estas HYDRAS comienzan con:
  - Capital inicial: **0 €**
  - Presupuesto inicial: **0 €**
  - Financiación externa: **0 €**
- No pueden utilizar dinero ficticio ni recibir una asignación inicial de capital.
- Su misión es demostrar que pueden construir un negocio real desde cero.

### 2. Objetivo de supervivencia
- Cada HYDRA fundadora dispone de un plazo máximo de **un mes** para conseguir al menos **50 USD de beneficio neto real**.
- El beneficio se calcula después de descontar **todos los gastos**.
- No se admitirán beneficios simulados ni ingresos ficticios.

### 3. Reproducción del ecosistema
- Una HYDRA solo podrá crear una nueva HYDRA cuando haya alcanzado el criterio mínimo de reproducción definido en este documento.
- El requisito económico mínimo es haber generado al menos **50 USD de beneficio neto real**.

### 4. Nacimiento de una HYDRA hija
- Cuando una HYDRA fundadora crea una nueva HYDRA, entregará **25 USD** de su propio beneficio como capital inicial de la nueva HYDRA.
- Ese dinero pertenece a la HYDRA madre y debe registrarse como una **inversión interna del ecosistema**.
- La HYDRA madre sigue siendo responsable de esa inversión.

### 5. Prohibiciones
- Está prohibido:
  - Inicializar HYDRAS fundadoras con dinero ficticio.
  - Utilizar capital simulado.
  - Mostrar beneficios inexistentes.
  - Crear estados iniciales con cantidades distintas a **0 €** (por ejemplo, 10.000 €, 50.000 € o cualquier otro valor).

### 6. Auditoría
- Tras cualquier actualización del Documento Madre:
  - Revisar todo el código fuente.
  - Revisar configuraciones, constantes y JSON de estado.
  - Revisar tests y documentación.
  - Corregir cualquier implementación que contradiga estas reglas.
- El Documento Madre prevalece siempre sobre cualquier otra documentación o implementación.

- **Objetivo absoluto:** lograr el **primer euro real** de ingreso.
- Todas las decisiones y tareas deben responder a la pregunta: *¿Acerca esto al primer ingreso real?*.
- Orden de prioridades:
  1. Productos
  2. Landing pages
  3. APIs funcionales
  4. Integraciones reales
  5. Captación de clientes
  6. Presupuestos
  7. Automatización comercial
  8. Facturación
  9. Cobro
 10. Primer beneficio
- La arquitectura seguirá evolucionando solo si es indispensable para vender.
